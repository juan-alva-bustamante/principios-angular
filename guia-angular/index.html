1. Conceptos clave de Angular

Antes de instalar nada, conviene tener claro el vocabulario básico. Todo esto lo vas a ver en código real en la Fase 3, pero es más fácil si ya sabes qué es qué.

¿Qué es Angular?

Angular es un framework para construir aplicaciones web de una sola página (SPA, Single Page Application): el navegador carga la app una vez y luego Angular se encarga de mostrar distintas "pantallas" sin recargar la página completa. Se escribe en TypeScript (JavaScript con tipos).

Componentes

Un componente es una pieza de interfaz reutilizable: su HTML, su CSS/SCSS y su lógica (TypeScript) viven juntos en una carpeta. Esto te va a sonar familiar: es exactamente la misma idea que usamos al repartir el maquetado en la Fase 1. Cada bloque que ya construimos se vuelve un componente:

Bloque del maquetado (Fase 1)Futuro componente Angular
App shell / layoutAppShellComponent
Sidebar — lista de chatsChatListComponent
Header del chat activoChatHeaderComponent
Hilo de mensajesMessageThreadComponent
Barra de entradaMessageInputComponent
Panel de info de contacto (TV)ContactInfoComponent

Componentes standalone (lo que vamos a usar)

Angular tenía antes un sistema de "módulos" (NgModule) obligatorio para agrupar componentes. Desde hace un par de versiones existen los componentes standalone, que no necesitan módulo: cada componente declara directamente qué otras piezas usa. Es más simple de entender para gente nueva, y es el default en Angular moderno — por eso es lo que vamos a usar.

Templates y data binding

El HTML de un componente puede "conectarse" con su lógica de tres formas básicas:

  • Interpolación — mostrar un valor: {{ nombreContacto }}
  • Property binding — pasar un valor a un atributo: [src]="avatarUrl"
  • Event binding — reaccionar a una acción del usuario: (click)="enviarMensaje()"

Signals (estado reactivo)

Un signal es una caja que guarda un valor y avisa automáticamente a la interfaz cuando ese valor cambia — por ejemplo, la lista de mensajes de un chat. Es la forma moderna y más simple de manejar estado en Angular, y es la que vamos a usar (ver Stack y convenciones).

Servicios

Un servicio es una clase de TypeScript que contiene lógica que no pertenece a un componente en particular — por ejemplo, la que obtiene los mensajes de un chat. Los componentes "piden" un servicio en vez de crearlo ellos mismos; Angular se los entrega (esto se llama inyección de dependencias). Por ahora basta con saber que existen.

Angular CLI

El CLI (Command Line Interface) es la herramienta de línea de comandos que crea el proyecto, genera componentes, levanta el servidor de desarrollo y compila la app para producción. Casi todo lo que hacemos en esta guía pasa por el comando ng.

3. Requisitos previos

Instala esto en orden. Cada quien lo hace en su propia máquina.

1. Node.js (versión LTS)

Angular necesita Node.js para funcionar (el CLI corre sobre Node, y Node trae npm, el gestor de paquetes que usamos para instalar todo lo demás). Instala la versión LTS (Long Term Support, la recomendada, no la "más nueva").

Recomendado: instalar Node con nvm (Node Version Manager) en vez del instalador oficial. Permite tener varias versiones de Node y cambiar entre ellas, lo cual evita problemas si más adelante otro proyecto necesita una versión distinta. 

# macOS / Linux — instalar nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash

# Cierra y vuelve a abrir la terminal, luego:
nvm install --lts
nvm use --lts

En Windows, usa nvm-windows o, si prefieres algo más simple, el instalador oficial desde nodejs.org (elige la versión LTS).

Verifica que quedó instalado:

node -v
npm -v
Nota: no importa memorizar el número exacto de versión. Solo confirma que node -v responde con algo como v20.x.x o v22.x.x (una LTS reciente) y no da error de "comando no encontrado".

2. Editor: VS Code + extensiones

Usamos Visual Studio Code. Instala estas extensiones (desde la pestaña de Extensiones, ícono de cuadritos en la barra lateral):

  • Angular Language Service (autocompletado y errores dentro de los templates HTML de Angular)
  • ESLint (avisa de problemas de código mientras escribes)
  • Prettier - Code formatter (formatea el código automáticamente)

3. Git

Confirma que ya lo tienes instalado (todos lo necesitamos, ya lo usamos en la Fase 1):

git --version

4. Instalar Angular CLI

Con Node ya instalado, instala el CLI de Angular de forma global (una sola vez por máquina):

npm install -g @angular/cli

Verifica que quedó instalado:

ng version

Esto debería mostrar la versión del Angular CLI, de Node, y del paquete de administrador de paquetes que estés usando. Si ves un error de permisos en macOS/Linux, evita usar sudo; es señal de que Node se instaló con permisos raros — normalmente se resuelve reinstalando Node con nvm (paso anterior).

5. Crear el proyecto (referencia para la Fase 3)

Este paso no lo hacemos todavía — lo hará quien cree el repo base en la Fase 3. Se documenta aquí para que todos entiendan qué comando se va a correr y por qué, antes de que exista. 

npx @angular/cli@latest new chat-equipo --style=scss --routing
OpciónQué hace
--style=scssUsa SCSS en vez de CSS plano en cada componente (igual que en el maquetado de la Fase 1)
--routingAgrega Angular Router desde el inicio, para navegar entre pantallas

No hace falta pasar una opción para "standalone": en las versiones recientes de Angular, los componentes standalone (ver Conceptos clave) ya son el comportamiento por defecto de ng new y ng generate.

Una vez creado, para levantar el servidor de desarrollo:

cd chat-equipo
ng serve

y abrir http://localhost:4200 en el navegador.

6. Estructura de carpetas

Así se ve un proyecto Angular recién creado (lo esencial):

chat-equipo/
├── src/
│   ├── app/
│   │   ├── app.component.ts        # componente raíz
│   │   ├── app.component.html
│   │   ├── app.component.scss
│   │   ├── app.config.ts           # configuración de la app (router, etc.)
│   │   └── app.routes.ts           # definición de rutas
│   ├── assets/                     # imágenes, íconos, etc.
│   ├── styles.scss                 # estilos globales (equivalente a nuestro main.scss)
│   └── index.html
├── angular.json                    # configuración del proyecto/CLI
├── package.json                    # dependencias y scripts
└── tsconfig.json                   # configuración de TypeScript

En la Fase 3, dentro de src/app/ vamos a crear una carpeta por componente (siguiendo el reparto de la Fase 1): chat-list/, chat-header/, message-thread/, message-input/, etc. Cada carpeta de componente trae junto su .ts, .html y .scss — el mismo principio de "todo lo de un componente vive junto" que ya usamos en el maquetado.

8. Stack y convenciones del equipo

Decisiones ya tomadas para que en la Fase 3 no haya que discutirlas de nuevo:

  • Componentes standalone, no NgModule (ver Conceptos clave)
  • SCSS para estilos, un archivo por componente — igual que en el maquetado
  • Angular Router para navegar entre la lista de chats y una conversación
  • Signals para el estado (mensajes, chat activo, etc.), en vez de librerías externas como NgRx — para un proyecto de aprendizaje, es más que suficiente y más fácil de entender
  • ESLint + Prettier para mantener el código consistente entre los 4

Nomenclatura de archivos

Angular tiene una convención de nombres que el CLI ya sigue automáticamente:

  • Carpetas y archivos en kebab-case: chat-header/
  • Sufijo según el tipo: chat-header.component.ts, chat.service.ts
  • Nombres de clase en PascalCase: ChatHeaderComponent

Si siempre creas archivos con ng generate, esto sale gratis — el CLI los nombra por ti.

9. Flujo de Git

Mismo espíritu que usamos en el maquetado: una rama por persona/componente, PR para integrar.

Nombres de rama

feature/chat-list
feature/chat-header
feature/message-thread
feature/message-input

Mensajes de commit

Un prefijo corto que dice qué tipo de cambio es, seguido de una descripción breve en español:

PrefijoCuándo usarlo
feat:Funcionalidad nueva
fix:Corrección de un bug
style:Cambios de estilos/CSS que no afectan lógica
refactor:Reordenar código sin cambiar el comportamiento
docs:Cambios de documentación (como esta guía)
 
git checkout -b feature/chat-header
git add .
git commit -m "feat: agregar componente de header del chat"
git push -u origin feature/chat-header

Después se abre un Pull Request hacia main y alguien más del equipo lo revisa antes de integrarlo.
